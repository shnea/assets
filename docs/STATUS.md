# 구현 확인 상태

2026-10-22 기준. 실제 실행 결과와 남은 확인을 구분한다.

## 확인한 내용

- Docker의 실제 PostgreSQL로 10개 통합 테스트 통과: 회원·관리자 소유권 분리, CSRF·PKCE, 변경 충돌, 이전 버전 보존, 아이디어 비공개·페이지 조회, 개인 분류 격리, 동시 업로드 예약·한도 감소, 연결 키 해제와 오래된 활성 키 표시, 플랫폼 에디터 문서·파일 관계, 스킬 내보내기와 백업 복원·실패 처리.
- 격리된 QA에서 서명된 OIDC 로그인부터 원본 파일 업로드·다운로드, 운영 통계 경계, 공식 MCP SDK의 조회와 즉시 연결 해제, 버전별 내보내기 및 파일 ID를 바꾸는 ZIP 복원까지 HTTP 검사 통과.
- 브라우저에서 플랫폼 에디터 Markdown 서식, 이미지 Ctrl+V, 별도 첨부 영역 Ctrl+V, 버전 저장·조회 확인. 문단 폭 제한과 저장 버튼을 덮던 하단 도구막대를 수정하고 PC·400px·800px 너비에서 확인했다.
- 브라우저에서 백업 ZIP 다운로드·파일 선택·복원 성공과 사용량 증가 확인. 다운로드 ZIP의 CRC와 원본 SHA-256도 확인했다.
- 설치된 Codex MCP 클라이언트에서 서버 초기화와 다섯 도구 발견 확인. 모델 턴이나 영구 설정 변경 없이 검증용 키를 해제했다. 도구 호출·파일 접근·버전 조회 자체는 공식 MCP SDK로 검증했다.
- MCP 연결 화면은 제품 선택 없이 주소·개인 연결 키를 제공한다. 직접 설정용 Streamable HTTP·Bearer 정보는 접어서 제공한다. Cursor·Claude Code·VS Code 앱을 직접 실행한 검증은 수행하지 않았다.
- 실제 개발 플랫폼의 프로젝트·환경 일치, 비공개·영구 파일 업로드, 해시·원본 다운로드 및 익명 접근 차단을 별도 검사로 확인했다. 이미지의 썸네일 JPEG·미리보기 WebP·원본 PNG를 각각 받아 파생본 생성과 원본 SHA-256을 확인했고 검사에서 만든 파일만 삭제했다.
- 운영 Compose는 이미지 참조만 사용하며 DB 바인드는 `/volume2/homes/myassets`다. 첨부 원본은 플랫폼에 저장한다. `.env`, `.env.prod`와 작업용 산출물은 Git에서 제외된다.
- API·웹·Nginx 이미지를 `registry.shnea.kr/assets-{api,web,nginx}:0.1.0-r1`로 게시했다. 레지스트리에서 다시 받은 세 이미지의 파일 계층과 실행 설정이 검사한 개발 이미지와 같음을 확인했다. 대상 플랫폼은 Linux amd64다.
- 개발 서비스를 최종 이미지로 갱신했고 개발 도메인의 상태 응답을 확인했다. localhost의 로그인 링크도 `https://dev-assets.shnea.kr`에서 인증을 시작한다.

## 운영자가 채울 설정과 검증 범위

- 운영 플랫폼 프로젝트·환경·키, DB 비밀번호, NAS 바인드 주소는 운영 템플릿에 입력해야 한다. NAS에는 적용하지 않았다. 사용자가 Compose와 `.env`를 복사해 실행하는 배포 방식이다.
- 실제 회원의 비밀번호를 입력한 플랫폼 로그인·로그아웃 전체 흐름은 에이전트가 직접 실행하지 않았다. 개발 도메인 연결·인증 주소·Secure 쿠키 설정을 확인했고, 전체 OIDC 서명·PKCE·콜백 흐름은 격리된 인증 서버로 검증했다.
- 긴 기간의 통계·대용량 파일·다른 MCP 클라이언트 앱은 별도 부하·호환성 검증을 하지 않았다. 외부 제작 도구를 조작하는 실행은 해당 도구가 연결된 에이전트 환경이 필요하다.

관리자는 타인의 자산 본문·제목·첨부·이전 버전을 열 수 없다. 연결 키는 원문을 저장하지 않으며, 플랫폼 키는 브라우저나 내보내기 파일에 포함하지 않는다.
