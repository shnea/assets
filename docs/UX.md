# 기록과 아이디어 수첩의 사용 흐름

## 작성 부담을 줄이는 기본 방식

자산은 질문을 따라 정리하는 가벼운 안내 방식으로 작성한다. 제작법의 핵심을 일정한 구조로 남기되, 처음부터 모든 항목을 채우도록 요구하지 않는다. 자산을 다시 읽고 다음 작업에 활용하는 화면을 제품의 중심에 둔다. 자유 메모는 아이디어 수첩에서 작성한다.

- 자산 작성의 기본 골격은 어떤 작업이었는지, 다음에 기억할 것은 무엇인지, 다시 시작할 때 무엇부터 해야 하는지다. 핵심 질문에 답하며 정리한다.
- 안내 항목에 실제 내용이 있으면 저장할 수 있다. 제목은 선택이며 비어 있으면 작성한 내용을 바탕으로 이름을 제안하고 사용자가 수정할 수 있게 한다.
- 분류, 사용 도구, 스킬, 플러그인과 참고 링크 등의 추가 정보는 필요할 때 펼쳐 입력한다. 안내 항목과 추가 정보를 모두 필수로 채우도록 강제하지 않는다.
- 미분류와 미완성 기록을 정상적으로 보관한다. 빈 선택 항목에 오류나 완성도 점수를 표시하지 않는다.
- 자산의 기본 편집 방식은 가벼운 안내로 고정한다. 자산 작성 화면에 메모 중심 작성 방식을 별도 선택지로 제공하지 않는다.
- 작성과 읽기 화면을 구분하되 같은 내용을 사용한다. 읽기 화면에는 빈 입력 항목을 나열하지 않는다.
- 초안 자동 저장과 버전으로 남기는 명시적 저장을 구분해 입력할 때마다 버전이 생성되지 않게 한다. 저장 중, 저장 완료와 실패를 구분하고 입력 내용을 보존한다.

## 아이디어 수첩

아이디어 수첩은 제작 자산과 구분된 사용자 전용 메모 공간이다. 제목과 분류를 정하지 않고도 떠오른 생각을 짧게 적고 나중에 다시 읽을 수 있다.

- 각 회원은 자기 아이디어만 작성, 수정과 조회할 수 있다. 운영 관리자도 다른 회원의 메모 내용에 접근할 수 없다.
- 아이디어는 MCP 제공 대상에서 제외한다. MCP의 목록, 검색, 상세 조회, 자료 및 관련 자료 조회에 아이디어의 제목, 본문과 첨부파일을 포함하지 않는다.
- 자산과 아이디어를 함께 저장하는 구현을 선택하더라도 MCP에서는 서버에서 자료 종류와 소유권을 모두 검사한다. 화면에서 메뉴를 숨기는 것으로 처리하지 않는다.
- 자산의 관련 기록이나 첨부 참조를 따라가며 아이디어가 MCP 응답에 섞이지 않게 한다.
- 사용자가 아이디어 수첩과 개인 자산의 차이를 알 수 있게 수첩 화면에 에이전트에게 제공하지 않는 개인 메모임을 표시한다.

## 화면 검토

사용자가 선택한 가벼운 안내 방식으로 자산 작성 화면을 구성한다. 아이디어 수첩은 별도의 자유 메모 화면이다. 내 자산과 아이디어 수첩, 작성과 읽기를 전환하며 확인할 수 있다.

초기 Figma 화면 검토 이후 저장 API·플랫폼 로그인·파일 업로드·MCP 연결을 실제 서비스에 구현했다. 개발 주소와 실행·검증 절차는 README와 DEPLOYMENT.md를 따른다.
